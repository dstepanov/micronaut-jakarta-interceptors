A binding annotation is an annotation meta-annotated with `jakarta.interceptor.InterceptorBinding`. An interceptor
class declaring it intercepts every element declaring it, and the two need not be compiled together.

[source,java]
----
@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Cached {
}
----

Declared on a class, the binding applies to every business method of that class, to its construction and to its
lifecycle callbacks. Declared on a method, it applies to that method alone. The two accumulate: a method is
intercepted by the interceptors bound to it and by those bound to its class.

The business methods of a class are the instance methods a caller invokes on it. Its lifecycle callbacks are
intercepted as callbacks rather than as methods, an injection point is not a call a caller makes, and the methods
of `Object` are none of the class's own even where it overrides them, so `toString`, `equals`, `hashCode`, `clone`
and `finalize` are not intercepted. A method that only shares a name with one of those - a `toString` that takes
an argument - is an overload rather than an override, and is a business method as any other method is.

A binding declared on a method that is not a business method binds nothing. It is not reported: a binding declared
on the class reaches such a method too, and there would be nothing wrong with that.

== Binding by member values

The members of a binding annotation are part of the binding, as the specification requires. An interceptor
declaring `@Cached(region = "users")` intercepts only the elements declaring the same region:

[source,java]
----
@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface Cached {

    String region() default "default";

    @Nonbinding // <1>
    String comment() default "";
}
----

<1> `jakarta.enterprise.util.Nonbinding` excludes a member from the binding, so two declarations may differ in it
and still bind to each other. That holds wherever the two declarations are: two annotations each carrying `@Cached`
with a different `comment` bring the same binding to a class, and nothing is reported.

The value a member defaults to is filled in before the comparison, so `@Cached` and `@Cached(region = "default")`
are the same binding. A default of an empty string or an empty array is no exception: `@Region("")` and `@Region`
are the same binding when `value` defaults to `""`.

A binding annotation declared in Groovy is the one exception. Micronaut records the default of one of its members
only when the default is a single constant - a string, a number, a boolean or a character - so a member defaulting
to an array, an enum constant or a class is a different binding spelt out than left out. Spell such a member out on
both sides, or leave it out on both, or declare the annotation in Java or Kotlin.

A method declaring a binding annotation its class declares as well replaces the class's declaration as a whole.
On a class declaring `@Cached(region = "users")`, a method declaring `@Cached` is bound to the region `default`,
not to `users`: a member the method leaves out takes its default, never the value the class gave it.

== Matching

An interceptor applies to an element when *every* binding annotation the interceptor declares is also declared by
the element. An interceptor declaring two bindings therefore only intercepts the elements declaring both, while an
element declaring more bindings than an interceptor is still intercepted by it.

A `@Repeatable` binding annotation is as many bindings as there are occurrences of it, and each occurrence is
matched as any other binding is. An element carrying `@Tag("one")` and `@Tag("two")` is intercepted by an
interceptor declaring `@Tag("one")`, and not by one declaring `@Tag("one")` and `@Tag("three")`; the order the
occurrences are declared in says nothing. A method declaring occurrences of a binding its class declares as well
replaces all of the class's occurrences of it, as a single binding declared twice would be replaced.

What is compared is worked out while the application compiles. The processor records the bindings of an
interceptor class and of each element it may intercept as the values of the binding annotations, with the members
they default to filled in and the members excluded from the binding left out, and the runtime compares those
values member by member as it resolves the chain of an element. Nothing is built from the annotations and nothing
reflects to compare them. The recorded values are read as they were recorded, without looking their defaults up
again: Micronaut keeps the defaults of an annotation in a registry the whole application shares, which the
reflection module adds to the first time it builds an instance of the annotation, and the bindings of an element
read the same before and after that.

A module that has to answer the same question - which interceptors apply to these bindings? - asks
api:interceptor.spi.InterceptorBindings[], which is the comparison the chains use. Micronaut CDI does so when its
`BeanManager` is asked for the interceptors of a set of bindings, so the two answers are the same. Its `values()`
reads the bindings back as the values of their annotations, as the processor recorded them, which is what a module
describing the bindings of an interceptor describes them from. A module comparing bindings one at a time - telling
whether two are equivalent, or comparing qualifiers that leave out their `@Nonbinding` members as bindings do - asks
api:interceptor.spi.BindingValues[], whose `normalize`, `matches` and `hashCode` compare one binding exactly as
`InterceptorBindings` compares a set of them: the defaults a value carries filled in, the members either side lists
as excluded left out, an empty string compared as the member left out, and of the members whose names start with
`$` only the two Micronaut reserves, `$nonBinding` and `$stereotypes`, left out.

== Bindings that come from elsewhere

A binding annotation declared on *another* binding annotation binds transitively: an element declaring
`@Critical`, itself annotated `@Monitored`, declares `@Monitored` too and is intercepted by the interceptors bound
to it. The other annotation need not be a binding annotation itself. A binding declared on any annotation binds
through it, on a class or a method alike, so a method declaring an annotation that carries `@Monitored` is
intercepted by the interceptors bound to `@Monitored` even when nothing else about its class is intercepted.

A binding annotation that is `@Inherited` is inherited by the subclasses of the class declaring it, so a subclass
of an intercepted class is intercepted without declaring anything of its own.

A binding that arrives that way may arrive twice. Two annotations declared together may each carry the same
binding with a different value, and the class then has no one answer to what that binding binds by; this is
reported as an error while it compiles:

[source,java]
----
@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Monitored(level = "high")
public @interface Critical {
}

@InterceptorBinding
@Retention(RetentionPolicy.RUNTIME)
@Monitored(level = "low")
public @interface Routine {
}

@Critical // <1>
@Routine
@Singleton
public class Ledger {
}
----

<1> `@Monitored` reaches `Ledger` twice, as `high` and as `low`. The class is rejected rather than bound by
whichever of the two was read last.

Stating the binding on the class itself is the answer to it. A class declaring `@Monitored(level = "high")` is
bound at that level whatever the annotations it declares carry, and nothing is reported: only two annotations
that both merely pass a binding along, with the class silent about it, disagree.
