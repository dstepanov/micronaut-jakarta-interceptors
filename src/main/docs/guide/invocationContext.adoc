`jakarta.interceptor.InvocationContext` is what an interceptor method is given. Its behaviour follows the
specification:

|===
| Method | Behaviour

| `getTarget()`
| The intercepted instance. `null` inside an `@AroundConstruct` method until it has proceeded.

| `getMethod()`
| The intercepted method for an `@AroundInvoke` method, and the callback of the intercepted class for a lifecycle
callback. `null` inside an `@AroundConstruct` method, and for a lifecycle callback of a class that declares none.

| `getConstructor()`
| The constructor of the target class inside an `@AroundConstruct` method, `null` otherwise.

| `getTimer()`
| The schedule of a method the scheduler invokes, as a api:interceptor.runtime.ScheduledTimer[]; `null` for
anything else. See <<timeout,Timeout Methods>>.

| `getParameters()`
| The arguments of the invocation, as a copy. Fails with an `IllegalStateException` for a lifecycle callback.

| `setParameters(Object[])`
| Replaces the arguments the rest of the chain, and finally the intercepted element, is invoked with. The count and
the types are checked.

| `getContextData()`
| A map shared by every interceptor of one invocation, and by any other Micronaut advice on the same invocation.

| `proceed()`
| Continues to the next interceptor of the chain and finally to the intercepted element.

| `getInterceptorBindings()`
| The binding annotations in effect on the intercepted element, as annotation instances.
|===

The bindings these accessors answer with are the ones the interception was resolved from. A binding a method
declares replaces the one of the same type its class declares, the whole of it, so a method that declares the
binding again and leaves a member to its default is bound by that default, and that is the value the accessors
report. Where a binding member is itself an evaluated expression it is reported unevaluated, as the comparison that
bound the interceptor read it.

An interceptor that returns without proceeding keeps the rest of the chain, and the intercepted element, from
running. For a lifecycle callback that is all it does: the bean is neither replaced nor discarded.

An exception thrown by an interceptor method reaches the caller unchanged, checked exceptions included: the
intercepted method is what the caller sees, and it declares them. That holds for a `private` interceptor method as
well, which is reached reflectively: the exception the reflective call wraps what it threw in is taken off again.

An `@AroundConstruct` method may throw what the constructor it interposes on declares, and lets through what the
constructor throws. The bean is then not created, and Micronaut reports it as it reports a constructor that is not
intercepted: a runtime exception thrown by the interceptor reaches the caller unchanged, and a checked exception, or
anything the constructor itself threw, is the cause of the `BeanInstantiationException`. Which checked exceptions a
constructor declares is not recorded, so one it does not declare is reported the same way rather than rejected.

`getParameters()` shows the arguments the intercepted element declares, and nothing else. A Kotlin suspending
function is compiled with a continuation of its own after them; that argument belongs to the language and is
neither shown nor asked for.

`proceed()` returns what the intercepted method returns from its call. For a suspending function that has
suspended, that is the marker `COROUTINE_SUSPENDED`, and the function completes after the interceptor has returned.
See <<limitations,Limitations>>.
