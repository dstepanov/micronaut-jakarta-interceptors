`jakarta.interceptor.InvocationContext` describes the intercepted element the way the specification does, which in
three places means the reflection of the platform: `getMethod()` returns a `java.lang.reflect.Method`,
`getConstructor()` a `java.lang.reflect.Constructor`, and `getInterceptorBindings()` instances of the binding
annotations. The types leave no way around it. Apart from `getConstructor()`, which Micronaut Core looks up, and
the instances of a binding whose builder `@RegisterAnnotations` generated, those accessors are answered by
Micronaut's reflection module, `io.micronaut:micronaut-reflection`, and fail in an application that does not have
it, see <<reflection,When Reflection Is Used>>.

Everything those three describe, Micronaut worked out while the application was compiled. Every context this module
hands an interceptor method also implements api:interceptor.MicronautInvocationContext[], which offers it:

.Java
[source,java]
----
@Interceptor
@Cached(region = "users")
public class CachingInterceptor {

    @AroundInvoke
    public Object invoke(InvocationContext context) throws Exception {
        if (context instanceof MicronautMethodInvocationContext micronaut) { // <1>
            ExecutableMethod<Object, Object> method =                         // <2>
                micronaut.getMicronautInvocation().getExecutableMethod();
            String region = micronaut.getInterceptorBindingValues().stream()  // <3>
                .filter(binding -> binding.getAnnotationName().equals(Cached.class.getName()))
                .findFirst()
                .flatMap(binding -> binding.stringValue("region"))
                .orElse("default");
            cache(region, method.getDeclaringType(), method.getMethodName());
        }
        return context.proceed();
    }
}
----

.Groovy
[source,groovy]
----
@Interceptor
@Cached(region = "users")
class CachingInterceptor {

            def method = context.micronautInvocation.executableMethod        // <2>

----

.Kotlin
[source,kotlin]
----

    @AroundInvoke

        if (context is MicronautMethodInvocationContext) {                   // <1>

            val region = context.interceptorBindingValues                    // <3>

        }

----

<1> every context of this module implements one of these, so the test always succeeds
<2> the declaring type, the name, the arguments and the annotation metadata of the intercepted method, as Micronaut
generated them
<3> the members of a binding that selected the interceptor, read as a value without building the annotation; "Reading
the bindings" below says why this rather than the metadata of the element

Kotlin and Groovy reach the accessors as properties, so `context.micronautInvocation.executableMethod` reads what
`getMicronautInvocation().getExecutableMethod()` returns.

== What each of them offers

|===
| Accessor | Instead of | Interface

| `getInterceptorBindingValues()`
| `getInterceptorBindings()`, and the typed `getInterceptorBinding(Class)` and `getInterceptorBindings(Class)`
| api:interceptor.MicronautInvocationContext[]

| `getAnnotationMetadata()`
| nothing - every annotation of the element, read as Micronaut reads metadata everywhere
| api:interceptor.MicronautInvocationContext[]

| `getMicronautInvocation()`
| nothing - the whole Micronaut invocation, for what the specification does not reach
| api:interceptor.MicronautInvocationContext[], narrowed by both sub-interfaces

| `getMicronautInvocation().getKind()`
| nothing - the specification has no counterpart
| api:interceptor.MicronautInvocationContext[]

| `getMicronautInvocation().getExecutableMethod()`
| `getMethod()`
| api:interceptor.MicronautMethodInvocationContext[]

| `getMicronautInvocation().getConstructor()`
| `getConstructor()`
| api:interceptor.MicronautConstructorInvocationContext[]
|===

api:interceptor.MicronautMethodInvocationContext[] is the context of a business method, a timeout method or a
lifecycle callback, and its `getMicronautInvocation()` is a `MethodInvocationContext`;
api:interceptor.MicronautConstructorInvocationContext[] is the context of an `@AroundConstruct` interception, and its
`getMicronautInvocation()` is a `ConstructorInvocationContext`. An interceptor that interposes on one kind names that
interface directly; one that interposes on several tests for api:interceptor.MicronautInvocationContext[] and branches
on `getMicronautInvocation().getKind()`.

`getAnnotationMetadata()` stays on the context itself because a Micronaut construction carries no metadata of its
own: the metadata of an `@AroundConstruct` interception is the one of the constructor, completed with the bindings of
the class.

== Reading the bindings

`getInterceptorBindings()` returns annotation instances, and Micronaut builds one as a dynamic proxy of the
annotation type, unless a builder was generated for it. `getInterceptorBindingValues()` answers with the same bindings
as the values of their annotations instead, and builds nothing:

[source,java]
----
// the specification's way: finds the instance among the bindings and calls the member on it
String region = context.getInterceptorBindings().stream()
    .filter(Cached.class::isInstance)
    .map(Cached.class::cast)
    .findFirst()
    .map(Cached::region)
    .orElse("default");

// the same answer, from the values of the bindings
String region = micronaut.getInterceptorBindingValues().stream()
    .filter(binding -> binding.getAnnotationName().equals(Cached.class.getName()))
    .findFirst()
    .flatMap(binding -> binding.stringValue("region"))
    .orElse("default");
----

The bindings are the ones that selected the interceptors, as the processor recorded them on the element: a binding the
element only inherits from the method it overrides is not among them, nor is a binding of the factory that produced
the bean, and occurrences of a repeatable binding that differ only in a member that does not bind are one binding,
reported once. Each value is the nearest declaration of its binding, the method's where it declares one and its
class's otherwise, taken whole, which is how the bindings selected the interceptors. A member a declaration leaves to
its default is left out of the value rather than filled in from the class, and the members that do not bind are there
as they were declared.

`getAnnotationMetadata()` is ordinary Micronaut metadata, and reads a binding as Micronaut reads any annotation: for a
method it answers from the method and its class together, merging a member the method leaves to its default with the
one the class gave it, and joining the occurrences of a repeatable binding of both. On a class declaring
`@Cached(region = "users")`, a method declaring `@Cached` is bound by the region `default`, while
`getAnnotationMetadata().stringValue(Cached.class, "region")` says `users`. Where the two differ, the values are what
bound the interceptor.

== Telling one lifecycle event from another

The specification lets one interceptor method interpose on more than one lifecycle event, and gives it no way to
ask which event it was invoked for:

[source,java]
----
@PostConstruct
@PreDestroy
public void lifecycle(InvocationContext context) throws Exception {
    if (context instanceof MicronautInvocationContext micronaut) {
        switch (micronaut.getMicronautInvocation().getKind()) {
            case POST_CONSTRUCT -> opened(context.getTarget());
            case PRE_DESTROY -> closed(context.getTarget());
            default -> { }
        }
    }
    context.proceed();
}
----

== The constructor of a proxied bean

A bean with around advice as well as constructor interception is constructed through the proxy Micronaut generated,
whose constructor takes a handful of arguments of its own after the ones the bean declares.
`getMicronautInvocation().getConstructor()` is the constructor of the target class regardless: the declaring type is
the bean, and the arguments are the ones the bean declares, which is what `getParameters()` lines up with.

== The whole Micronaut invocation

`getMicronautInvocation()` carries the `MethodInvocationContext` or `ConstructorInvocationContext` the interception
is part of, for what the specification does not reach - the generated executable method or bean constructor, the
kind of the interception, the arguments as a named map, the attributes shared with every other advice on the same
invocation, and whatever a later version of Micronaut adds:

[source,java]
----
MethodInvocationContext<Object, Object> invocation = micronaut.getMicronautInvocation();
Object id = invocation.getParameters().get("id").getValue();   // an argument by name
----

WARNING: Do not call `proceed()` on it. That is what the last interceptor method of the chain proceeds into, so
proceeding it directly runs the intercepted method while skipping every interceptor method the specification has
yet to invoke. Call `proceed()` on the `InvocationContext` instead, which is the chain the specification describes.
The same goes for replacing arguments: `setParameters(Object[])` on the `InvocationContext` checks their count and
their types, and shows an interceptor only the arguments the intercepted element declares.

== Reflection

An interceptor written against these accessors reflects on nothing, whatever it reads, and needs no reachability
metadata of its own in a GraalVM native image, nor the reflection module. With that module the accessors of the
specification work beside them, and an interceptor may use both. See <<reflection,When Reflection Is Used>>.
