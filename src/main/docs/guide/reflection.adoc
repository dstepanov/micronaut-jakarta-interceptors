The interception itself reflects only to invoke an interceptor method that is declared `private`.

An interceptor method is invoked through the `io.micronaut.inject.ExecutableMethod` Micronaut generates for it at
compilation time, which dispatches through generated code. An interceptor method that has no executable method is
an error at resolution rather than a fall back to reflection. The interceptor chain of an element is read from the
annotations the processor left on it, the interceptor instances come from the bean context, and the proxy of an
intercepted bean is a generated subclass.

Generated code cannot call a `private` method of another class, which the specification nevertheless allows an
interceptor method to be. For one of those the executable method Micronaut generates calls it through
`java.lang.reflect.Method`, by way of `io.micronaut.core.reflect.ReflectionUtils`, and the processor declares
`@ReflectiveAccess` on the method, which is what has Micronaut generate that call. An interceptor method that is
package private, protected or public is called directly, so declaring interceptor methods with at least package
private access keeps every invocation of them free of reflection.

Three accessors of `InvocationContext` do reach for the reflection of the platform, because the types the
specification has them return leave no choice:

* `getMethod()` returns a `java.lang.reflect.Method`;
* `getConstructor()` returns a `java.lang.reflect.Constructor`;
* `getInterceptorBindings()` returns instances of the binding annotations.

`getInterceptorBinding(Class)` and `getInterceptorBindings(Class)`, which the specification added beside the whole
set, build only the binding asked for rather than the set to filter it.

All three are resolved only when an interceptor asks for them, and remembered afterwards. An application whose
interceptors do not call them, and declare no private interceptor method, never reflects at all; the binding
comparison the interception does is made against the annotation metadata Micronaut recorded at compilation time,
and builds no annotation.

== Reading the interception without reflecting

Nothing forces an interceptor through those three. Every context this module hands an interceptor method also
implements api:interceptor.MicronautInvocationContext[], which offers the same description as Micronaut compiled
it - the executable method, the bean constructor and the annotation metadata - and reflects on nothing. An
interceptor written that way needs no reachability metadata of its own. See
<<micronautApi,The Micronaut Invocation Context>>.

== In a native image

In a GraalVM native image such a lookup answers only for a member the image was told to keep. The processor
declares `@ReflectiveAccess` on the members the specification has these accessors return - the constructor of a
bean whose construction is intercepted, its lifecycle callbacks and the business methods that are intercepted -
which `micronaut-graal` turns into the reachability metadata of the image while it compiles the application.
`getMethod()` and `getConstructor()` therefore answer inside an image as they do on a virtual machine, and an
application declares nothing for them. Only the members that are actually intercepted are kept.

`getInterceptorBindings()`, and the typed accessors beside it, are covered the same way. Micronaut builds an
annotation instance as a dynamic proxy of the annotation type together with
api:core.annotation.AnnotationValueProvider[], and a native image defines that proxy only when it was told to. The
processor declares `@ReflectionConfig(type = ..., accessType = DYNAMIC_PROXY)` on an intercepted class for every
binding annotation of the class, its constructor and its business methods, which `micronaut-graal` turns into the
registration of that pair. This needs Micronaut Core 5.2 or later.

A private interceptor method is covered by the `@ReflectiveAccess` the processor declares on it, which
`micronaut-graal` turns into the metadata the reflective call needs, so it is invoked inside an image as it is on a
virtual machine, and an application declares nothing for it either.

That is verified rather than asserted. The `test-suite-graalvm` and `test-suite-java` modules run inside a native
image through the `nativeTest` task, their interceptors call all three accessors, `test-suite-java` declares a
private interceptor method, and neither declares any reachability metadata: an interception that reached for
reflection the image was not told about would fail there rather than pass unnoticed on the JVM.

An application whose interceptors call none of the three and declare no private interceptor method needs nothing
at all. Nothing else of the interception - the chains, the bindings, the ordering, the invocation of the interceptor
methods that are not private, the parameters, the lifecycle and the construction - asks for any metadata.
